I learn software much faster when there is a real annoyance on the other side of the code.

A small utility forces surprisingly concrete questions: where should state live, what does the desktop actually expose, what happens on Wayland, how does the program recover when an assumption fails, and how do you package the result so someone else can run it?

The project can be tiny while the lessons are not.

## Useful is enough

Not every project needs to become a startup or a giant framework. Sometimes the right scope is one weird problem on one machine, solved carefully enough that somebody else with the same problem can use it too.

That's a kind of software I want to keep making.
